# TinyWarp 0.1.1 菜单界面审阅

日期：2026-11-12。模式：full。用户明确指出菜单项顺序和分隔线不自然，本轮范围为本地应用下拉菜单、更新状态及菜单内键盘操作；不审阅设置页正文、账号功能或全局主题。

## 范围与依据

框架为原生 Rust / WarpUI，使用项目 `Menu`、`MenuItemFields`、`Appearance` 与既有主题 token。已核对 `AGENTS.md`、`CONTRIBUTING.md`、`gui-ui-guidelines` 和现有菜单实现。没有引入 CSS、另一套组件库、依赖或新动画。

按 `better-interface` 的顺序应用 accessibility、layout、writing、typography、colors、UI 六个领域，并以 `make-interfaces-feel-better` 检查排版、表面、动画、图标和性能。以下审阅不是全应用可访问性认证。

| Domain | Evidence inspected | Result |
| --- | --- | --- |
| Accessibility | 菜单导航／激活源码、共享菜单回归、真实 GUI 中方向键与 Enter 进入设置 | 修正禁用项导航与激活；VoiceOver 与触发器 AX 语义未验证 |
| Layout | 本地菜单生成、所有更新阶段行数及顺序回归、真实菜单截图 | 常用设置在前，维护项在后；分隔线只分开这两组，状态变化不插入新行 |
| Writing | 检查、下载／校验、重启、设置、快捷键及日志动作映射 | 去掉重复品牌和状态／动作混写，文案与动作一致 |
| Typography | 项目默认 12pt UI 字号、186pt 菜单宽度、短标签与实拍截图 | 沿用项目排版；未以缩小字号容纳长品牌文案 |
| Colors | 现有语义 token、默认深色实拍 PNG 的文字／背景像素 | 正常文字 RGB 232/232/232、背景 30/30/30，对比度 13.606:1；浅色及交互态未测量 |
| UI | 既有菜单圆角、阴影、悬停／选择源码与静态渲染 | 保留组件样式；没有新增装饰、图标或运动 |

| Category | Evidence inspected | Result |
| --- | --- | --- |
| Typography | 短标签、默认字号与实拍 | 已检查；浏览器 CSS 字体平滑／换行规则不适用于 WarpUI |
| Surfaces | `Menu` 圆角、阴影、内边距及截图 | 沿用项目表面与密度；未调整全局主题 |
| Animations | 下拉菜单条件渲染与 Hoverable 状态 | 没有自定义菜单动画，浏览器 10% 动画回放不适用 |
| Icons | 现有齿轮入口与菜单文字项 | 保留项目图标体系，没有为四个清晰动作添加装饰图标 |
| Performance | 状态模型观察与菜单渲染 | 通知驱动，无轮询、动画循环或新增依赖；未做性能压测 |

## Findings

| Severity | Domain | Location | Before | After | Why |
| --- | --- | --- | --- | --- | --- |
| HIGH | Accessibility | `app/src/menu.rs:1966`、`app/src/menu.rs:2075` | 无初始选择时方向键默认指向第 0 项；Enter 不检查整项是否可选 | 首次向下／向上分别选择首个／末个可用项，全禁用时不选；激活入口拒绝不可选项 | 禁用状态必须约束键盘行为，不能只约束外观和鼠标；已修正并覆盖共享菜单回归 |
| MEDIUM | Layout | `app/src/workspace/view.rs:10080` | 更新独立放在设置前，分隔线把它与日志等维护项拆开；就绪时再插入重启行 | 设置、键盘快捷键 → 分隔线 → 更新、查看日志；更新始终占一行 | 按用途与使用频率分组，固定动作位置，避免更新阶段导致菜单结构跳动；已修正 |
| LOW | Writing | `app/src/workspace/view.rs:10080` | `检查 TinyWarp 更新`、`更新已就绪，重启 TinyWarp`、`查看 TinyWarp 日志` | `检查更新`、`重启并更新`、`查看日志`；忙碌时为 `检查更新中…`、`下载并校验中…`、`重启更新中…` | 应用内菜单无需重复品牌，动作先行并保持简短；同时减轻固定宽度菜单的排版压力；已修正 |

## Considered but rejected

| Location | Candidate | Rejected because |
| --- | --- | --- |
| 本地应用菜单 | 删除所有分隔线 | 常用设置与更新／日志有清晰的用途差异；保留一条安静的组间分隔即可，不让更新独占一组 |
| 共享 `Menu` | 全局重画颜色、圆角与阴影 | 用户明确关注顺序与分组，现有组件静态渲染没有给出需要改变全局样式的证据 |
| 本地应用菜单 | 给每行添加图标或进场动画 | 短标签已能辨认动作，常用下拉菜单适合即时反馈；新增装饰不改善这次问题 |

## Verification

在日常 TinyWarp 的专用终端标签中运行本轮 `.note/0.1.1-polish/verify.sh`，使用仓库锁定依赖、Rust 1.92.0 与既定 SDK／Metal 环境。Rust 测试以临时 HOME 和系统沙箱运行，禁止访问日常与 Preview 数据；本机没有 nextest，沿用编译后的 libtest 程序。

定向过滤器为 `menu::tests::`、`tinywarp_version::`、`autoupdate::tinywarp::`、`autoupdate::tests::`、`workspace::view::tests::local_terminal_`，单线程执行涉及全局通道配置的测试。覆盖菜单固定顺序／行数、真实模型通知刷新、焦点、选择、忙碌、无更新、失败、重复检查、取消重启和禁用项键盘行为。

真实 GUI 路径使用：

```sh
WARPUI_USE_REAL_DISPLAY_IN_INTEGRATION_TESTS=1 \
WARP_INTEGRATION_TEST_ARTIFACTS_DIR="$PWD/.note/0.1.1-polish/gui-artifacts" \
/usr/bin/sandbox-exec -f .note/0.1.1-polish/isolation.sb \
target/release/integration test_local_terminal_settings_open_once_and_return_to_terminal
```

步骤为展开菜单 → Down → Enter → 实际设置页 → 重复打开复用 → 返回原终端执行 `printf`。该夹具禁用更新入口，因此截图验证设置／快捷键／日志分组；更新各状态通过真实 Workspace 模型回归验证，没有把截图当成下载与重启界面的完整验收。

严格检查为：

```sh
cargo clippy --locked -p warp --lib --tests --bin warp-oss --no-default-features --features tinywarp_gui -j2 -- -D warnings
cargo clippy --locked -p integration --bin integration --no-default-features --features tinywarp_gui -j2 -- -D warnings
```

最后只对本轮 Rust 文件执行项目相同配置的 formatter，不重复格式化后的测试或 lint，不运行完整 presubmit。最终检查结果和公开候选状态见 [0.1.1 交付记录](0.1.1-update-menu.md)。原始截图、记录和像素测量在忽略目录 `.note/0.1.1-polish/`。

## Verdict

已确认的三项问题均在本轮修正。`Approve` 仅适用于以上源码与已检查的菜单范围；不代表整应用或所有主题已完成可访问性验收。

Not verified：VoiceOver、浅色与悬停／选中／禁用态的实测对比度、macOS 辅助功能缩放、跨平台和性能压测；日常应用升级后的最终顺序与分组由用户按约定验收。没有以这些未验证项制造虚假的失败或通过结论。
