## 实际键盘操作

前置测试窗口后，下列路径通过键盘执行，并观察真实界面或焦点内容：

| 路径 | 操作与结果 |
| --- | --- |
| 终端输入与执行 | 输入 `printf 'TinyWarp keyboard OK\n'` 并回车，输出正确，返回命令输入 |
| 新标签与分屏 | `⌘T` 创建第二个终端标签；`⌘D` 创建右分屏，独立库回读为 2 个 Tab、3 个终端 pane |
| 命令面板 | `⌘P` 打开，方向键出现可见选择；`Escape` 关闭后焦点内容回到命令输入 |
| 设置入口 | `⌘,` 新建设置标签并默认打开外观；上／下方向键切换侧栏，能够进入关于页 |
| 返回终端 | `⌘W` 关闭设置标签，`⌘L` 回到命令输入，两个终端标签和分屏仍在 |
| 正常退出 | `⌘Q` 正常退出，退出码 0；重新启动后两标签、三分屏和原 UUID／目录／测试历史保留；再次正常退出码 0 |

以上只覆盖相应快捷键、选择和焦点反馈。命令面板中文查询输入未取得可靠工具证据，不列为通过；未验收其全部搜索与激活动作。原始应用日志、隔离状态与数据库回读在 `.note/product-foundation-2026-11-16/`，没有记录用户私人命令。

## 控件可达性缺口

本次外观页与关于页分别测试 Tab／Shift-Tab，未进入图标下拉、版本复制或仓库链接，也未观察到对应控件的独立可访问节点或可见焦点。设置侧栏导航可用，不等于页面内操作可达。

| 严重性 | 位置 | 当前行为 | 建议改后行为（未实施） | 原则与影响 |
| --- | --- | --- | --- | --- |
| HIGH | `app/src/settings_view/mod.rs` 的 `focus`／`input_tab`；`app/src/view_components/dropdown.rs` 的闭合入口；`app/src/settings_view/about_page.rs` | 设置默认聚焦搜索；Tab 处理只覆盖特定页面，图标下拉、复制和链接没有通用焦点遍历。与本次 Tab／Shift-Tab 观察一致 | 沿既有焦点系统建立页面内控件顺序、可见焦点、键盘激活及关闭后返回；同步回归真实控件 | 仅键盘用户无法完成这些页面操作；应在共同的焦点边界解决，不能只给一个控件添加孤立快捷键冒充全页可用 |

下拉展开后的内部菜单已有方向键、Enter、Escape 动作；这次没有通过键盘打开闭合入口，因此不把“菜单内部有绑定”列为端到端选择已通过。共享焦点机制的实现属于后续具体修复，不在本轮验收中顺带重做全套控件。

## VoiceOver 的验证边界

静态核对显示：`AccessibilityContent` 经 `crates/warpui/src/platform/mac/window.rs` 与 `objc/window.m` 写入窗口并发送 announcement；`objc/host_view.m` 主要暴露文本区域，焦点数据沿 View 响应链取得。目标路径中的原生树没有逐一暴露自绘按钮、链接与下拉选项，因此窗口公告不能证明完整控件树和读屏激活可用。

VoiceOver、动态公告的实际朗读、系统减少动态效果、完整缩放与对比度矩阵均为 Not verified。下一轮应在用户允许开启读屏后，验证名称／角色／状态、动作、焦点恢复及更新状态公告；不提前宣称无障碍兼容。

结论：Block，仅针对上述设置页面内控件的键盘可达性。表中通过路径保留其局部结论；读屏验收待后续完成。
