# TinyWarp L3A：隔离后台内存基线

2026-11-10。已完成用户批准的后台内存协议与保护复核：先验证本地控制接口，再测后台资源；前台输入／滚动另测。结果为现场粗粒度基线，不作精密性能比较。本阶段不改应用功能，不安装或替换日常 TinyWarp。

## 构建与测量对象

应用源码 `944a4fd23f45ab188931f2b366319bfe88d40212`，Rust 1.92.0、仓库原 release profile、GUI feature，无 opt0 开发覆盖。构建和打包在 Warp Preview 的独立标签执行，保留父进程链证据；北京时间 13:27:48—13:41:46，共 13 分 58 秒，退出码 0。候选签名、身份、无 App Group entitlement、schema、bundled 资源与系统依赖检查通过。

普通 OSS 优化包未开启 `WarpControlCli`。测量入口 `control_main.rs` 通过既有 `ChannelState.additional_features` 只增加该运行开关，复用同次构建匹配的优化 warp／warp_core 库；仅链接入口也在 Warp Preview 完成，没有重编应用库。原有权限仍需用户在测试 UI 中主动启用，未绕过鉴权。

用户已在隔离测试包启用控制模式。`app.ping`／`app.version` 返回正确实例身份，隐藏窗口后的新建标签／分屏／关闭实测可用，未抢占前台。无需安装系统 CLI，直接调用包内 `--warpctrl`。测试包缺少安装所需 `Contents/Resources/bin` 包装脚本，对应源码安装函数会返回 wrapper not found；这与控制服务可用性是两件事。

控制服务及曾打开的设置页缓存计入本次应用内存。没有成对测得可独立扣除的控制服务开销，因此不能把数字直接当作日常未优化开发包或普通 OSS 包的内存。

## 隔离与协议

- 测试 HOME 位于 `/private/tmp`，使用唯一 `dev.warp.TinyWarpL3A*` 身份及原生偏好域；不依赖 release 下无效的 `WARP_DATA_PROFILE` 隔离。
- 测试进程继承内核文件访问限制，拒绝真实 TinyWarp／Preview 配置、Application Support、原生偏好与 Group Containers；实际拒绝访问检查通过。原数据库仅核对文件元信息，不读内容、不迁移。
- 固定 Hack 14、120 列／40 行、非竖向标签、50000 行滚动容量，关闭自动启动和会话恢复。实际固定项与样本一致；应用自动写入的默认脱敏正则单列核对，不覆盖用户设置。
- **同一进程连续三轮**，不是三次独立启动；每轮前后均回到一个终端 shell。始终隐藏测试窗口，每个样本检查未在前台；通过精确 PID、窗口／标签 ID 调用本地接口。
- 每个稳定窗口目标约 15 秒，每次读取后休眠 1 秒；实际间隔包含读取与调度开销。顺序：单标签空闲 → 6 标签／8 pane → 关闭并等 shell 回收 → 20 次开关标签后的即时／回收状态 → 新标签内 10 万行 PTY 输出 → 关闭并等回收。保留默认 60 秒撤销关闭行为，默认值见 `app/src/undo_close/settings.rs`。
- application 为主进程加同包辅助进程；shell／其他子进程列入 children。RSS 可能重复计算共享页，physical footprint 为主要指标。CPU 是相邻样本仍存活 PID 的累计 CPU 时间差，可能漏掉短命子进程。
- 10 万行由测试 zsh 专用信号 trap 产生；输出标记和 signal 响应只证明测试 shell 完成相应动作，不代表键盘到像素延迟或滚动帧率。`vmmap` 在定量采样结束后收集。

工具与复现步骤见 [测量工具说明](../../script/tinywarp-perf/README.md)。原始采样、失败记录、测试数据库、源码哈希、构建与保护证据保存在 Git 忽略目录 `.note/l3a/`；公开结果只保留数字及必要环境信息，不提交用户数据、控制凭证或端点。

## 排除记录与限制

先前前台尝试受应用焦点及显示器变化影响，部分轮未完成，部分轮混用外接 1x 与内建 Retina 显示条件；全部留存但不并入后台结果。窗口移动的原因没有被确认为应用缺陷，定位试验工具中的强制定位／缩放操作已经移除。

后台第一条关闭请求同时带具体标签和 `--active`，接口拒绝了冲突选择器；改为只指定具体标签后验证成功，失败目录保留，未计入最终三轮。

现场其他应用、系统缓存及内存压力未固定；隐藏窗口也不代表渲染器完全未初始化。本基线用于后续相同协议的比较，不证明冷启动性能、长期无泄漏、前台流畅度或相对原 Warp 的收益。


## 三轮结果

下表为每个采样窗口 application **physical footprint 中位数，单位 MiB**。三轮有先后顺序且共用进程，不能把范围当作独立重复试验的误差区间。

| 场景 | 第一轮 | 第二轮 | 第三轮 |
| --- | ---: | ---: | ---: |
| 单标签空闲 | 150.6 | 219.6 | 265.1 |
| 6 标签／8 pane | 174.4 | 238.6 | 285.2 |
| 关闭多标签并等 shell 回收 | 175.0 | 239.2 | 285.8 |
| 20 次开关标签后即时 | 252.8 | 302.9 | 351.2 |
| 20 次开关标签后等 shell 回收 | 219.1 | 265.8 | 320.5 |
| 新标签内 10 万行输出后 | 222.8 | 272.7 | 337.0 |

children 组相应中位数：单 shell 约 2.9 MiB，8 pane 约 23.4—24.9 MiB，反复开关标签后即时约 61.2—65.3 MiB，等额外 shell 退出后恢复约 2.9 MiB，输出场景的两个 shell 合计约 5.8 MiB。关闭多标签后额外 shell 的退出等待分别为 60.08、60.22、60.10 秒，与默认撤销期吻合。

应用组仍逐轮增长：每轮反复开关标签后、等待 shell 回收的读数，比该轮开关前高约 44.1、26.6、34.6 MiB。两者之间存在应用缓存、分配器、系统压缩与控制服务等影响；目前只确认增长现象，不能据此认定泄漏或直接归因于 AI／持久化加载。定量窗口结束后的逐进程快照中，约 98% 的应用 footprint 在主进程，同包辅助进程约 8.2 MiB；随后 `vmmap` 已采集，诊断时刻与定量窗口不同。

采样实际为每窗 **5—14 个点**，最长相邻间隔约 **6.87 秒**；第二轮开关标签后回收窗口仅 5 个点，读数置信度较低。窗口内峰值会漏掉短暂峰值。标记检测的 0.15 秒只是循环休眠；检查进程与系统调度也耗时，不能当作有效计时精度。完整 RSS／footprint／CPU、每窗点数与实际间隔、标记耗时见 [数字结果](l3a-results.json)。

## 验证与交付

- 后台三轮各 6 个采样窗口完整结束；18 组汇总逐一从原始样本重算一致，每个样本检查测试包隐藏且不在前台。结束后正常退出测试包，残留测试进程为 0。
- C／Swift 工具严格编译、Rust 测量入口 `-D warnings` 元数据检查、Python 语法／统计自检、进程归属与无效 PID 检查通过；Preview／日常 TinyWarp 目标会被拒绝。原有应用逻辑没有变化，未跑全工作区测试。
- 当前实际运行采用隔离启动探针和 `background.py` 接续；仓库内整理的 `launch_control.py` 完成语法及参数检查，尚未再次走一遍新的完整 UI 授权流程。
- 构建前后 5,786 个既有输入文件哈希一致；8 个受保护配置文件哈希一致。原数据库及辅助文件 inode 保留，仅取元信息；原 Warp Preview 进程持续运行。没有覆盖设置、导入数据、改数据库格式或安装系统 CLI。
- 本阶段提交测量工具、协议及脱敏数字，不包含测试数据库、控制凭证、原用户文件或构建产物；本地提交，不推送。

下一步优先定位反复开关标签后主进程保留的对象，并补一个不启用控制服务的对照，再选择优化点。后续收益必须使用相同优化 profile 和测试条件比较；尚未证明本阶段降低了日常 TinyWarp 内存。前台输入／滚动及三个独立启动的性能仍未测量。


## C1 复用样本时的更正

C1 验证发现，旧 fixture 的 `override_opacity = 1.0` 不符合 schema 要求的 1—100 整数百分比，应用会提示无效并使用默认值。共享 fixture 已更正为 `100`。上述历史采样仍是旧 fixture 的原始结果，不回填、不宣称它实际采用了显式 100% 覆盖；后续若要精确比较，应以同一份有效 fixture 重采。用户已决定暂停专项性能研究，本轮不重做基准。
