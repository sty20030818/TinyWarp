# TinyWarp L3C7：内置输入分类器与词库评分后端

2026-11-11，在 C6 及其补验提交 `5f4e18396` 后继续精简。目标是停止创建内置 AI 输入分类器，移出具体启发式分类和词库评分实现，保留终端共用输入类型、shell 工具、外部 CLI 及旧设置数据。

## 实现与共用边界

`input_classifier` 新增默认开启的 `heuristic` 能力，`natural_language_detection` 将原评分算法及词库放在默认开启的 `word_scoring` 模块中；shell 语法检测保留在无后端也可使用的入口。原评分逻辑与 shell 检测经过拆分前后源码核对，未改变算法。共享 `InputType`、分类来源及协议类型保持原值。

工作区继承关闭默认能力；完整应用通过 `input_classification` 显式恢复，既有 ONNX／启发式开关同步关联该能力，独立组件默认仍保留原实现。`evaluate` 研究命令要求启用真实 `heuristic` 后端，不提供空分类器替代。TinyWarp 的产品图中 `input_classifier` 与 `natural_language_detection` 均没有开启具体分类／评分 feature。

`InputClassifierModel` 保留共用模型接口，以 `Option` 明确表达后端缺席；本地模式以及未编入分类能力时不创建分类器，调用方先检查是否存在。自动检测守卫同时检查编译能力和本地模式，旧策略即使启用自动识别也不会启动该路径。完整能力下的非本地模式继续创建原分类器，不伪造恒定 shell 分类结果。

`rust-stemmers` 同时经 `tantivy -> warp_search_core` 服务终端共用搜索，因此保留，其他共用正则及基础库也保留。实际 macOS arm64 normal/build 依赖图为 891 → 891 项，完整 GUI 仍为 975 项，无新增包。本批不宣称包数量下降；具体分类实现、词库评分模块与其初始化路径已退出 TinyWarp。

原先应用对词库 crate 的直接依赖没有调用方，已删除；Cargo.lock 仅同步删除 `warp -> natural_language_detection` 的直接依赖条目，全部包名、版本、来源和其余条目保持一致，经离线检查确认，没有升级依赖。

依赖门禁在原包边界外新增具体 feature 边界，防止分类／评分能力重新被编入；在真实 Cargo 图上临时开启被禁止 feature，门禁按预期拒绝。保留共用词干库，不将“整个依赖包还在”误判成专用后端回流。

## 已运行验证

组件、应用测试、GUI 集成、严格检查和候选编译均在 Warp Preview 执行，开发候选应用增量编译 1 分 58 秒。该产物复用 release 依赖缓存，但应用使用 opt0；这不是整个阶段耗时，也不是正式性能基准。

- 词库两配置及分类器三配置编译／测试完成，共 17 项测试；无后端分类器配置原本没有内部测试，未虚增计数。shell 语法、完整词库评分、已有启发式输入和 v2 工具用例保持可用。
- TinyWarp 157 项、完整应用 156 项定向回归通过，合计 330 项单元／组件测试；覆盖不创建分类器、完整非本地模式保留分类器、旧策略不能开启精简构建的自动识别及现有本地持久化行为。
- 四项 GUI 集成回归通过：免登录首次启动、旧账号记录／历史／标签保留、外部 CLI 不受旧 Agent 默认设置影响、设置页正常打开及复用。
- 五种组件配置、两种应用配置共七组严格 Clippy 通过；正向与实际违规功能图的反向依赖门禁均通过。
- 独立候选九项包检查通过，19 个配置 schema 分区与 C6 JSON 语义一致，140 项资源匹配，23 项动态库依赖均来自系统。
- 打包候选的隔离副本通过真实 zsh 和 `/bin/cat` 字节输入输出；设置截图已查看，显示正常。OS 菜单新建终端标签和向右分屏成功，shell 数 1 → 2 → 3，实例正常退出。
- 临时测试库中十组旧记录正常启动／退出后均保留，包括五种已有和一种未知语言服务器配置，未使用真实用户数据库。

## 修正、会话复用与证据

首次应用测试编译发现模型初始化误用了不存在的 API，已改为生产相同的单例注册方式，并重跑受影响应用测试。一次构建会话退出后保留了已通过组件与 TinyWarp 测试，从完整配置继续。依赖门禁曾过度排除被 Tantivy 共用的词干库；查清消费者后仅修正门禁与依赖核对，Rust 源码及已通过的回归／严格检查未变，只续跑相关边界和候选构建。失败记录分别保留在 `.note/l3c7/attempt1-test-model-api/`、`attempt2-build-session-ended/` 和 `attempt3-shared-stemmer-boundary/`，不采用失败步骤冒充成功证据。

用户明确要求固定复用同一个 Preview 构建窗口／标签，已将此约定写入 [开发说明](build-macos.md#日常开发与快速验证)，并记录本机 shell PID、TTY 和应用身份于忽略的 `.note/tinywarp-build-session.json`。后续先核对并复用空闲会话；激活后等待窗口恢复，不以短暂读不到 AX 窗口作为另开窗口的依据。本阶段后续步骤在同一已记录的 shell 内执行，没有更改 Preview 设置。

当前最终证据见 `.note/l3c7/acceptance-final.json`，其他构建、测试、图、签名、截图及保护记录位于同目录；这些临时数据与构建产物不提交。

## 数据保护与交付限制

原生副本使用独立身份、临时 HOME、空 URL 注册和文件访问沙箱，禁止访问真实 TinyWarp／Preview 配置、Application Support、原生偏好、Group Containers 和 `~/.aws`；测试子进程不继承 AWS 环境变量，旧记录只注入经路径和身份校验的临时数据库。
