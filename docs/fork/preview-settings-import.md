# Preview 本地设置导入

日期：2026-11-10。用户明确决定开始日常使用 TinyWarp，要求将 Preview 设置导入；不是导入账号或合并终端使用数据。本轮沿用阶段结束本地提交、不推送的约定。

## 迁移结果

源配置为 `~/.warp-preview`，目标为 `~/.warp-oss`。继续使用已有设置入口修复开发包 `.note/candidates/L2-settings-fix-dev/release/bundle/osx/TinyWarp.app`，身份仍为 `dev.warp.WarpOss`。没有重新编译，也没有替换或卸载 Preview。

两个应用包的 schema 根身份不同，但 230 个设置叶的契约、默认值完全一致。按保留功能选取 124 个本地 GUI 设置叶进行比较；不是只复制外观，也不把能云同步的普通本地偏好误排除。

- 导入 23 项源文件中显式保存的本地偏好，包括外观、字体、标签／分屏、通知、隐私、启动目录、补全、别名展开、终端滚动容量、SSH 和应用启动行为。
- 5 项目标已有显式值而源未显式保存的偏好，删除目标显式值以恢复相同缺省语义：应用图标、竖向标签主要信息、竖向标签视图模式、`honor_ps1` 和输入框类型。不能仅合并源显式值，否则目标残留覆盖会继续改变体验。
- 导入 1 份键位文件中的 2 个自定义快捷键：补全建议与接受自动建议。action ID 沿用原名，两项在 TinyWarp 仍有消费者。
- 导入 2 份 Tab 配置。只复制已保存配置，不打开它们；两份均为终端 pane，无命令、参数、Agent 或云 pane。不等于导入正在运行的标签、历史或进程。
- 源未发现额外自定义主题、工作流或启动配置目录，因此没有补复制不存在的资源。

按 schema 默认值比较得到 11 个配置差异，但这不是 11 项实际界面行为变化的证明；部分输入设置有运行时投影。缺省字段采用源相同的省略语义，不把 schema 默认值逐项固化到用户文件。

账号、云同步、Agent、AI 字体和 Notebook 等 8 项源显式字段不导入，目标既有值保留。没有读写 Keychain，没有复制 App Group、账号缓存、MCP、索引、完整源 NSUserDefaults 或任一 Preview 数据库。`general.login_item` 是用户本地启动偏好，可以迁入 TinyWarp；`AppAddedAsLoginItem` 是平台登记状态，不能冒充偏好复制，也未手动改变 Preview 的系统登记。

目标原配置、目标原生偏好及目标 SQLite 的在线备份保存在 Git 忽略目录 `.note/settings-import-20261110/backup/`，目录权限 0700，文件权限 0600。SQLite 备份从只读连接生成，`quick_check` 通过；未打开 Preview 数据库。正式记录与 Git 均不包含实际偏好值、项目路径、Tab 文件内容或备份数据。

原设置仍可用于恢复。若以后需要恢复，先正常退出 TinyWarp，再比较并选择性还原配置；导入后用户的新调整也必须保留，不能直接整目录或整库回滚。

## 验证与实际切换

源与目标使用 TOML 1.1，系统 Python `tomllib` 不支持其中的多行内联表，不能把它的解析失败当作配置损坏。本轮使用仓库已缓存的 `toml_edit 0.25.6+spec-1.1.0` 和 JSON Schema 2020-12 校验器独立检查，没有引入依赖或构建应用。独立转换器的 TOML 1.1／基本类型／嵌套与错误隐私检查通过，schema 校验器的合法与非法 fixture 通过。

源配置、目标原配置和迁移候选分别通过各自 schema；候选 TOML 往返 JSON 语义一致。额外使用注册设置叶白名单，避免 schema 允许未知属性时误导入账号或未知键。键位 YAML 的键和值形状正确，两个 Tab TOML 解析通过。两个目标资源路径此前不存在，无覆盖冲突。
