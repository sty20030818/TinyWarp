# 设置中文与菜单图片

2026-11-16。用户确认四项一起实现；当前为本地候选，尚未进入公开版本。

## 使用变化

- 新建设置标签显示“设置”。旧快照中单独设置页的默认 `Settings` 标题在显示时转换，原快照标题不改写；其他标签名称保持原值。
- `Warpify` 设置页显示为“Shell 与 SSH 增强”，说明子 Shell／SSH 的命令分块与输入编辑，以及 SSH 远程辅助程序的安装选择。原设置键、页面 slug 与连接行为沿用。
- 保留的终端快捷键动作使用中文，继续支持英文名称和按键搜索；已有自定义按键与内部 ID 保留。沿用共同候选过滤，补齐已停用的独立编辑器及此次发现的 AI／分享条目，原注册与处理器保留。
- 在“设置 → 外观”选择菜单图标图片，预览后立即用于右上角菜单按钮；可恢复默认齿轮。命令面板也能查找“选择菜单图标图片”与“恢复默认菜单图标”。

## 图片存储与失败行为

使用现有图片库解码 PNG／JPEG，按方向信息旋转、居中裁成 128 × 128 PNG，再由原 Avatar 组件圆形显示。文件最大 10 MB，单边不超过 8192 像素，总像素不超过 1600 万。

选择结果只保存在当前数据目录的 `menu-icons/custom.png`；日常 OSS 配置对应 `~/.warp-oss/menu-icons/custom.png`。规范化图片是唯一持久选择，没有新增数据库字段、TOML 设置或镜像清单。移走原图不影响已导入副本。

图片解码、裁剪及保存放在后台。临时文件写入、同步后原子替换；失败保留旧选择并显示错误。共享忙态防止跨窗口重复导入，带文件版本的缓存键和模型通知让菜单与预览同步刷新。恢复默认只删除这一张自有图片；启动遇到坏文件则回退齿轮，允许重新选择或恢复默认。

macOS 原生选择器的现有 `Image` 类型可能列出其他图片格式；实际导入仍严格只接收 PNG／JPEG，并给出明确错误。没有为这个入口扩展公共文件选择类型。

## 原生选择器修复

首轮独立候选从命令面板打开选择器时触发真实崩溃：AppKit 在 `NSOpenPanel` 初始化中同步查询输入法位置，再次进入仍被借用的 Rust 应用上下文，出现 `RefCell already borrowed`。对应日志和同 bundle ID／PID 的 crash 报告已核对。

在 macOS 文件选择器的共同入口将整个创建、配置与显示延后到主队列执行，让外层应用动作先结束。沿用既有成功／取消回调和所有权，不在菜单图片入口另建一套选择器。修复后的候选已实际打开原生选择器，并记录取消回调完成；未再出现该次 fatal。

- 图片回归使用临时目录，覆盖原图移走、重启读取、保存失败、损坏文件、缓存更新、恢复默认与异步通知。
- 中文目录 8 项测试、应用严格 Clippy、Apple Silicon 构建与签名校验通过；真实打包检查 5 项通过。Rust 与原生改动已做最终格式化。
- 真实界面已观察到“设置”标签、默认外观页、“Shell 与 SSH 增强”的完整用途说明，以及英文 `menu icon` 对应的中文命令。最终候选的快捷键列表首屏已实际显示中文；全部候选的文案完整性由上述生产注册回归检查。

- 期间用户也在测试副本中选择了自己的图片；重启前后保存图片哈希一致。恢复默认验收完成并正常退出后，已将该选择的私有副本恢复到同一测试 Profile；没有删除用户原图或替换日常安装。

## 用户验收后的头像样式调整

用户已验收四项功能，随后反馈首次选择头像时短暂出现主题色外圈，并要求只显示头像、移除设置下方的说明。

主菜单此前给所有 Avatar 都设置了主题色圆底；本地图片冷缓存加载时露出底色，不透明图片加载后才遮住。自定义头像现在取消圆底和鼠标悬停的外层填色，设置预览也使用透明底。默认齿轮、圆形裁剪、原点击区域、菜单提示及更新红点沿用；图片存储与会话数据结构没有改动。设置只删除常驻说明，导入错误仍会显示。

这次仅调整两处调用点的显示样式，不为样式属性新增重复单元测试。新候选已通过应用构建、严格 Clippy、8 项中文目录测试、打包签名及最终格式化。实际通过原生选择器导入一张带透明区域的新 PNG，主菜单与设置预览都只显示图片内容，无主题色圆底，常驻说明已消失。

验收后通过同一原生入口恢复用户原头像，图片哈希与验收前一致；测试副本正常退出码为 0，数据库 `quick_check` 为 `ok`，原 2 个标签、1 个终端与 1 个设置页保留。用户另行关闭了日常应用的“纵向标签页布局中隐藏搜索栏”，顶部搜索框已观察到显示，未通过命令行修改日常配置。
