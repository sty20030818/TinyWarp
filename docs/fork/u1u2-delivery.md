# TinyWarp U1/U2：本地更新与安全重启

2026-11-12，本阶段复用 Warp 的更新状态机、退出确认和会话持久化，接入 TinyWarp 自己的本机更新包。没有新增依赖，没有修改数据库 schema，也没有安装到日常应用目录。

## 行为

右上角齿轮打开本地应用下拉菜单，包含版本、检查更新、准备完成后的“重启更新 TinyWarp”、设置、快捷键和日志。继续隐藏账号、登录、同步和云功能。此前更新项挂在不可见的头像菜单上，本轮已统一标题栏入口与浮层的显示条件。

菜单显示简化的日期构建号，悬停提示完整版本；本地菜单宽度为 320。完整 `WarpVersion`、二进制内版本和 bundled 资源版本仍用于更新判断与验证，不以显示文本作为版本身份。

U1/U2 只接收目标实例自己的 `tinywarp-updates/inbox`，没有向 Warp 官方查询更新。投递方式：

```sh
script/tinywarp-stage-update /绝对路径/TinyWarp.app --data-dir /目标实例的/Application\ Support/目录
```

必须明确指定实例目录；工具只准备更新收件箱，保留旧收件箱，不替换应用或改写设置。包需要通过版本、架构、SHA256、文件所有者及私有权限检查，解压后核对应用身份、可执行文件、资源版本、签名和架构；安装目录不可写时提前拒绝。此入口信任当前用户本机准备的文件，不能替代远程发布签名。

只有明确点击重启更新才进入安装流程，普通退出不暗中应用更新。仍有命令时复用退出确认；取消后取消重启状态。允许退出后，先将当前会话快照提交到 SQLite 并取得确认，再完成原有 writer 关闭与进程退出。保存失败则取消更新；关闭会话恢复的用户仍保留该选择。

独立 helper 在 GUI、账号和数据库初始化之前运行，确认旧进程真正退出后复制并验证完整候选包，再用 macOS 同卷原子交换替换应用。完整旧包保留在安装父目录 `.tinywarp-previous-*`。新进程启动失败或在就绪前退出时换回旧应用并重新启动；不回退数据库或用户配置。新进程仍存活但超时未确认时保留旧包并记录失败，不强杀可能已开始的用户任务。当前没有自动清理历史完整备份。

## 验证

- 174 项相关应用、持久化及更新回归通过；新增两项菜单动作／禁用状态回归通过。最终显示调整未增加与实现同义的测试。
- 严格 Clippy 通过，菜单修正及最后的版本显示调整分别完成增量构建与签名。构建均在 Warp Preview 现有窗口的新终端标签运行。
- 隔离真实测试确认损坏包在换包前拒绝、安装目录只读时在退出前拒绝；原应用继续运行。
- 真实 helper 换包与新进程启动失败回退分别通过，标签、分屏、历史、文件配置与外部 CLI 输入输出完成独立回读。
- 用户确认修正版齿轮能展开菜单、能看到重启更新；运行 `sleep 600` 后出现退出确认，取消后测试终端仍在。日志记录第一次更新动作后原进程继续运行，稍后第二次点击更新才正常退出。
- 第二次真实界面更新安装到 `_03` 后，独立回读确认 2 个标签、3 个 terminal pane 身份、2 条原测试历史和所有配置文件哈希保留，新增 1 条测试历史；新包与完整旧包签名有效，二进制分别匹配目标与原版。首次以过期 PID 回读未通过，随后依据安装结果和实际新进程归属重新核对，没有将失败检查记为通过。

用户随后指出完整版本号被截断，最终候选已缩短显示并加宽菜单；严格检查、构建通过，最终显示外观仍待人工复看。更早的合成键鼠触发未取得有效证据，不计作界面验收；实际菜单和取消由用户操作确认。后台 helper 成功与界面点击证据分开记录。
